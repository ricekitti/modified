# v1.8.15 - Bridge Egg Clutch and remaining independent Quick Buy helpers

- Adds Bridge Egg Clutch under Player, preserving the recovered BridgeEgg attempt state machine, controlled-player fall prediction, throw-angle search, packet support confirmation, correction handling, one-tick slot restoration and timer ownership.
- Seven source settings: Lowest Y 40 (0-255), In void for OFF, Time 0.5s (0.5-5), Wait for Clutch ON, Pre timer speed 1.0x (0-1), After timer speed 0.03x (0-1), Use Stasis instead OFF. Time is visible only with In void for; Use Stasis instead hides both timer controls. Bind remains unassigned.
- Use Stasis instead performs the source module's own position/motion suspension and moveEntity cancellation. It does not toggle or rewrite the existing native Stasis feature. Owned motion is restored only while the source's identity, position and correction guards permit it.
- Missing VoidProximity is explicitly adapted from the recovered PearlRescue support-column semantics, checking the egg trigger's sampled footprint columns down to Y=0 with the same collision-box solid predicate. Unloaded columns conservatively suppress this trigger. This is an adaptation, not recovered byte-identical VoidProximity behavior. Missing SupportUpdate and trajectory-properties holders are reconstructed as data holders from their construction/read sites; the throw solver itself comes from the separate recovered Trajectories source, whose hash/path are retained.
- Both pearl variants now coordinate with the actual registered Bridge Egg canSave query. Native Clutch is read through its enabled/planned-target state; native Scaffold and native Stasis implementations are unchanged.
- Ports the independent Quick Buy catalog/item matching, five-preset model, quantity/order controls, profile JSON serialization, shop/category-slot matching and preset editor into isolated dev.rice helpers. The editor layout/interactions use a small vanilla rectangle/color adapter instead of loading Valen's ClickGUI framework. Model changes expose a dirty revision for later host persistence integration.
- Quick Buy helpers are compiled and tested but are not exposed as a working Auto Quick Buy module or purchase loop. Native editor-launch/key/persistence integration remains part of the blocked feature. PurchaseConfirmation and its Status state machine are still missing from the supplied recovery evidence; no guessed confirmation or blind clicking is shipped.
- Keeps v1.8.13 Auto Pearl and v1.8.14 Fireball Pearl Clutch behavior, source defaults and documented host adaptations. No foreign startup, auth, licensing or telemetry is loaded. Previous versioned EXEs are preserved; project and Windows file/product versions are 1.8.15.0.

Validation: full 32-test CTest suite, including named/SRG/official integration runs. Each mapping executes 22 Auto Pearl checks, 13 Fireball Pearl Clutch checks, 21 Bridge Egg checks and 21 independent Quick Buy helper checks. Additional native checks cover distinct descriptor/event slots, settings counts, persistence namespaces, the Clutch query and a real native queued self-disable. Egg checks exercise actual use packets, delayed restoration, support updates, source suspension/move cancellation and correction/unload cleanup. Quick Buy checks exercise count caps, immutable snapshots, permanent upgrades, order changes, malformed/duplicate profile entries, serialization, reserved/category/shop slots, ordinary-chest rejection and editor preset cycling. Existing module regressions remain in the suite. The versioned EXE's decoded DLL must match the rebuilt DLL before packaging completes.

Not verified: live Lunar/BedWars gameplay, real-server egg/pearl/fireball outcomes and anticheat interaction. The dormant Quick Buy editor's GPU appearance has not been visually tested. Restart Minecraft before injecting.
