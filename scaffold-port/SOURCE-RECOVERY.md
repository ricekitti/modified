# Source recovery and evidence boundaries

Repository: ricekitti/rise-open at c08acf7223ce9a6cde453cf86f97d77d92c742ba. Parent/submode Git blob ids are retained in rise-source/manifest.json. No original/restored client JAR is present in the repository artifacts or releases, and the user confirmed that they do not have one.

The readable com.alan.clients files were recovered with CFR 0.152 from C:/classdump/out. Their source version is unverified. Some game classes in that dump are stubs (for example Entity.class has no fields), so the dump is not a complete original runtime. Empty historical rise-decompiled/V*Mode.java files are not implementation evidence. The full readable parent at rise-decompiled/Scaffold.java and recovered named submodes are supplemental static evidence, not proof of 6.9.7 provenance.

The analysis here used shell javap/CFR and repository files. It is not retained REA-engine evidence, a recorded live trace, or original-client execution.

## Inventory selection and history

- Primary SlotUtil-aik uses the source eligible-block predicate and ItemStack-co previous count > 5 OR current stack count > 20. It selects the first eligible hotbar entry.
- ItemStack-co initializes history age well beyond 20; InventoryPlayer-g advances the age and copies the current count after twenty ticks.
- PlayerController-d resets age to zero and decrements the previous-count snapshot after canPlaceBlockOnSide succeeds, before sending/attempting onItemUse. A later failed item use still consumes this history attempt. A rejected can-place predicate does not.
- InventoryPlayer-g separates the source shadow-slot held accessor from the visible/raw accessor. Destination hooks therefore cover both held-item reads and controller synchronization. The port never writes visible currentItem.
- The source Render Boolean is passed to SlotComponent.b(slot,render). It controls the slot/count HUD; it is not a request to visibly change the selected hotbar slot. The panel now has its selected item icon, hotbar block total, layout and animation; source fonts and shader passes are adapted to the destination renderer.

## Global timing and packet ordering

- PacketTiming-ao has priority-zero observers and checks cancellation. A non-sentinel outbound block-use packet resets placement age. Incoming S08 resets correction age. Local S12 records three velocity components and resets velocity age; sufficiently large upward/horizontal velocity also resets significant-velocity age.
- World-w increments these counters during entity update. The destination uses observed entity-tick timestamps, retaining unknown pre-injection history as unknown.
- EventBus sorts descending priority. BadPackets-bb is priority four and does not check cancellation. Its attack/entity-use and inventory flags are the two queried by the parent's placement guard; movement packet subclasses reset them. This component runs before module dispatch. The late timing component runs after dispatch and excludes final canceled/held packets. No-event packets bypass both components once.
- The packet-order implementation covers the two flags queried by the parent plus held-slot and placement/dig flags queried by Vk; movement resets all four. No packet is canceled by that observer itself.

## Downwards and Watchdog Sprint

- Primary Vb and recovered VerusDownwards agree on physical-sneak input, a recent-placement window of twenty ticks, integer-height/falling predicates, a fifteen-pass reset delay and downward offset. Their field aliases differ.
- Watchdog Downwards' effective branch is in the parent: six full-block passes, axis-aligned yaw, held sneak and the consumed-press modulo-three exception. Its offset overrides the earlier upward offset and cancels the parent's edge request. The primary Entity source establishes the real one-use edge flag as crh; it is not mapped onto another module's global flag.
- Vn/WatchdogSprint forces sprint, chooses 0.083 or 0.118 for speed potion, retains the signed 0.1 recent-correction penalty and applies heading-based additive drag. Cleanup releases owned input; unrelated flight/timer state is not clobbered.

## Telly, rotations and timer

- The readable parent supplies the effective-mode selector: right-click-only Telly uses Normal when use is released; Disable On Flag uses Normal for ten eligible placement packets after correction age one. Repeated callbacks in the same tick cannot rearm recovery.
- Watchdog Telly has a delayed-ground-jump heading branch, diagonal-ascent filter, quantized downward ascent aim, a deduplicated 45-degree yaw/pitch probe search, separate normal/boost step ranges and a held-jump-only boost predicate. Those branches now have their own implementation.
- Prediction Telly uses its own click ticks, arc/window readiness and six-block probe sweep. The source D prediction sweep and standalone placement predicates are ported; cross-module Speed/Sprint state remains unavailable.
- The dump's raycast override checks ae plus two double fields named crI/crK, while the primary Entity source uses crI/crK for other types and crM/crO for recorded X/Z velocity. Treating the dump's two doubles as the packet-recorded horizontal velocity is an inference from matching types, reset context and thresholds. This cannot be established conclusively without original bytecode; tests prove the chosen implementation, not that unresolved alias mapping.
- Visual Back Rotations' model state is reconstructed from the parent PostMotion handler. Destination rendering applies its yaw/pitch in a scoped wrapper around the existing player renderer. Primitive snapshots restore only unchanged owned fields, even if rendering throws. Other entities and first-person view are excluded. This replaces Rise's custom model-pitch fields with a destination rendering adaptation.
- Parent Timer writes only when target/facing/block geometry exists and the setting differs from one. Destination cleanup adds ownership checks, menu/world release and yielding when another writer changes the speed. This is an intentional lifecycle adaptation required by the user's ownership constraint.
- New Watchdog Rotations retains the unusual block-centre-to-side-vector calculation, twelve-degree target step and key/speed-dependent output offsets. Nonzero yaw offsets also use the source one-key diagonal-motion addition when movement correction and Watchdog Jump do not own it.

## Safe Walk and HUD continuation

- Primary Entity-c declares boolean crh, enters the X/Z/diagonal edge loop when vanilla grounded-sneaking OR crh is true, then resets crh after the loop. This establishes behavior independently of the readable dump's conflicting crd alias. Primary Scaffold's lifecycle also clears crh. Probe distance defaults to -1.0 and each axis shrinks by 0.05.
- Replacing only isSneaking in vanilla movement cannot implement the independent airborne branch: vanilla first requires onGround. The destination therefore wraps the three moveEntity calls in EntityLivingBase.moveEntityWithHeading, pre-clamps only the local Scaffold-owned request and calls the original virtual method once. Other entities, vertical displacement and original exceptions pass through. The fixed nine-class table is preserved; bootstrap SlinkyHooks16 adds one native declaration.
- The recovered parent requests protection when offset cells two and three below are replaceable and sneak is released. Rise's separate Speed integration is absent. Its nonempty Vantage session gate is deliberately replaced with a valid destination world/player context; no Rise network session is invented or queried.
- Source SlotComponent.bN totals ItemBlock stacks in slots 0..8, including blocks the placement selector would reject. Main inventory stacks are excluded. A shadow non-block item displays only its icon, and a matching visible non-block item is hidden. Menu/claim/stack/Render predicates are covered separately from rendering.
- The panel's retained item/count/width, centered placement at scaled height minus ninety, 22-pixel height, 1.0/1.1 scale endpoints and 900 ms exponential animation follow the recovered source. Standard destination fonts/theme and a rounded layered underlay adapt the original font, blur and bloom integrations.
- The actual item/font painter uses the existing framework GlStateScope, both projection/model-view matrix stacks, the original matrix mode and still-owned RenderItem.zLevel. Tests record GL calls and inject an item-render failure to check cleanup. They do not constitute live GPU validation or pixel comparisons.
- Native GUI pause clears owned Scaffold movement/timer/key/slot/visual/HUD state without clearing the global packet components. Enabling in the menu defers sprint startup packets/camera claims until normal input is available. Actual world-unload events remain delivered during menu pause. These are distinct lifecycle boundaries, covered by the Java/JVM fixtures.

## Vk/vo/Wa continuation

- Vk ground heading/correction gates, axis/diagonal/potion multipliers, extra-placement count, airborne drag, block-change observations, jump-release rotation/start-Y probe, landing-slot predicate and known child-setting level predicate are implemented. The unusual source `(posX, prevPosY-2, posY)` block probe is preserved. The empty Place Extra blocks output branch remains unresolved, despite the setting's known effects on drag and counters.
- vo supplies modulo-three ground-packet Y offset, consumed sneak presses, half-speed timer and C03, plus priority-four modulo-one jump cancellation. A real vanilla jump call-site hook now carries cancellation; it calls the original virtual method once otherwise and preserves its exception. Explicit Vk disable emits its known one/two ground packets; failure to send still releases all state. Suspend/unload skip replay.
- Wa has independent launch/ascent/block-height stages, potion scales, side/minimum strafe gates, forward input scaling, collision-tested three-step stationary alignment, placement offsets/rotations and non-ice upward-placement counters. Its literal mid-handler move-counter reset is preserved; intended cadence and unreachable later branches cannot be inferred from the cleaned source. Empty Tick/Jump listeners are not treated as proof that the original did nothing.
- The native bind hook only latches a request for the enabled Scaffold descriptor when Wa is armed. Java consumes it on a motion pass, and the source velocity window queues one disable through the existing module queue. Other modules and hold binds keep their existing route. No JVM call runs on the input thread.
- Wa/Vk PreMotion rotation requests use a scoped walking-packet adapter with priority arbitration, finite-angle checks and compare-before-restore semantics. Camera rotation and original walking exceptions survive scope cleanup; client coordinates are never rewritten by this adapter.
- Rise Speed/Disabler/Flight/LongJump/Blink dependencies are not mapped to unrelated destination modules. The default independent path is implemented. Source helper continuation after disable, a ground jump after toggle, and unconditional Wa disable strafe are omitted under the user's state-ownership constraint. No foreign Blink queue is flushed, and timers/keys/rotations are released immediately on suspend/unload/disable or mode changes. These are explicit adaptations, not recovered parity.
- Bootstrap is now SlinkyHooks17 with 34 declarations; the nine-entry hook table ABI remains fixed. Eight Java suites run in each namespace, plus 20 native tests. No live original-client comparison has occurred.

## Parent state and placement continuation

- The readable parent supplies two temporary counters. Input captures forward/strafe before zeroing them while `blockInputTicks-- > 0`; Snap uses the captured heading. Pause decrements during first-pass sneak scheduling, forces owned sneak with Sneak off and suppresses direct `placeBlock` work above three ticks. Disable/suspend/world cleanup clears both counters. A scan of available `com.alan.clients.*.class` files found those field strings only in the three Scaffold copies; it does not prove there are no reflective or missing external writers. No trigger is invented.
- Parent enable seeds yaw to camera minus 180 plus the chosen offset, and pitch to 90. Readable Watchdog Jump pre-update branches now preserve the recent-correction stop, early/settled ground rotations, side-key last-writer ordering, 0.9895 multiplier, stationary held-jump override and potion/sneak slowdown. The independent default uses 140 degrees. Alternate 147/117 degrees require Rise Speed, which is absent in the destination.
- Early rotation requests are retained only when later main-mode rotation does not publish a request. This preserves source ordering in the destination's rotation adapter without stepping twice merely because two source requests were issued. Exact original arbitration and random/FPS jitter remain unverified.
- Placement now retains the falling UP preference, reused-face grounded Same-Y raycast fallback, Strict top-face retry, supported-ground start-height resynchronization and actual movement predicate. Counter/rotation tests and the actual parent loop with game objects exercise the readable behavior. The original parent also queries static Rise Sprint prediction flags before selecting a slot; that absent movement-module integration is not mapped to an unrelated destination feature.
- A ninth Java suite covers these branches in named, SRG and official mappings. Fixtures remain separate from live client evidence.
